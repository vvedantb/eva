# Changelog — November 2026

## Eva Android companion app (apps/mobile) - 2026-11-07

- New `apps/mobile`: Expo SDK 57 / React Native 0.86, set up like vmem's mobile app. Built on `@vvedantb/native-ui` (auth, floating tab bar, `/ai` chat parts). Android only, sideloaded as an APK, package `com.vis1.eva`.
- Tabs: Inbox (`notifications.list`), Sessions (new `mobile.listChats`, recent open sessions across every accessible repo), Settings. A chat screen shows the transcript, docks the agent's question in place of the composer (as the web does), and replies to session chats through `sessionWorkflow.enqueueMessage`. Quick tasks and projects are read-only, with "Open on web".
- Push: new `pushTokens` table and `push.ts` (Expo Push API, drops `DeviceNotRegistered` tokens). It sends for `mention` and `routed_question` notifications (`createNotification`), and for new agent questions (`pendingQuestions.post`, not on a re-post). Each push carries the chat `target`; `notifications.chatTarget` stores the same id for the inbox.
- The question parser and answer builder moved to `@eva/shared/pendingQuestion`, so web and mobile read and answer questions the same way.
- The root `react` override is scoped: `@eva/mobile` gets 19.2.3, the version React Native 0.86 needs. `PublicConvexUrlEnv` is now a string map, because Expo's `process.env` type failed TypeScript's weak-type check.
- Screenshot pass fixes: added `react-native-css-interop` (NativeWind's JSX runtime does not resolve under pnpm's isolated linker, so the bundle failed), a web build target for previews with a no-op `push.web.ts`, and list times moved to `ListRow` `titleEnd`.
- Sessions tab marks a session whose agent waits on your answer: `mobile.listChats` returns `isAwaitingAnswer` from the web sidebar's `awaitingAnswerEntityIdsForRepo`, and the row shows the web's warning help-circle in place of the status dot.
- Agent replies render markdown (`react-native-marked`, `useMarkdown`, so no list nests in the chat scroll) and fold their tool steps behind the web's summary line ("Read files, ran commands"). The new `@eva/shared/activityTrace` reads steps with Zod and no `@vvedantb/ui` types.
- UI parity loop, round 1: native-ui gained `MessageContent bubble="tint"` (Eva's `bg-primary/10` user bubble) and a `/markdown` entry styled from the web `markdown.css` (vvedantb/packages#133). `apps/mobile` pins `@vvedantb/native-ui` to that merged commit (`github:vvedantb/packages#537a99f&path:/packages/native-ui`) until a release reaches npm; root `onlyBuiltDependencies` allows its `prepack` check.
- UI parity loop, round 2: native-ui `ChoiceQuestion` (vvedantb/packages#134) replaces the app's chip `QuestionDock`: Eva's web dock card with lettered rows, descriptions, "Other...", Back and Next/Submit. Pin moved to `76cfe73`.
- UI parity loop, round 3: native-ui `AgentTraceFold` and `MessageMeta` (vvedantb/packages#135). Mobile chat now folds finished turns behind "Worked for …", shows copy (`expo-clipboard`) and the clock under each message, heads each day with Eva's day divider, and uses the web placeholder "Ask Eva anything...". `formatDayLabel`, `formatClockTime` and `findDayBoundaryIds` moved to `@eva/shared/dayLabel` (dayjs only), shared by web and mobile. Pin moved to `6cbf730`.
- Push on a real phone still needs a Firebase `google-services.json` and an `EAS_PROJECT_ID`. See `apps/mobile/README.md`.

## Quick task and project preview tools menu matches sessions - 2026-11-05

- The preview ⋮ menu in quick tasks lacked "Select element", "Freeze animations" and "Pop out preview". They were gated on session-only props.
- "Freeze animations" is now always shown; it never needed a chat.
- "Select element" sends into the task chat through `useTaskAnnotationSend`. `agentTaskChatWorkflow.enqueueMessage` now takes `displayContent`, and the task queue drain shows it, same as sessions.
- The mini-player source now carries a session or task `owner` instead of `sessionId`. Its stale check reads the task doc for tasks. Quick tasks pass a `returnTo` of `/quick-tasks/<numId>/sandbox/preview`.
- Projects get the same: `useProjectAnnotationSend`, `projectChatWorkflow.enqueueMessage` takes `displayContent`, and Pop out returns to `/projects/<numId>/sandbox/preview`. The mini-player `owner` is now any `SandboxOwner`.
- Drift guard: `SandboxPaneSlots` now requires `onAnnotationSubmit` and `miniPlayer` (no optional preview-tool props), so a surface that skips one fails `tsc`. All three chats share one send rule, `annotationSender`.

## Sandbox git token cache follows the real token expiry - 2026-11-05

- Cause of "Failed to publish task branch" on carepulse-ts quick task 277: every push failed with GitHub "Invalid username or token". The helper served a token fetched at 13:29 UTC; it was already dead at 14:10 UTC.
- `@octokit/auth-app` caches installation tokens for up to 59 minutes, so `/api/git-credentials` can return an old token. The in-sandbox helper then cached it for a fixed 50 minutes more, past GitHub's 60-minute expiry.
- `/api/git-credentials` now also returns `expiresAt` (unix seconds). `git-credential-eva` caches until 5 minutes before that time. A response without `expiresAt` is not cached. Old-format cache files read as expired.

## Unread dot on the Manager Ave launcher - 2026-11-04

- Ave's replies had no unread signal: the "done" pop lasts 3 s, then the launcher went idle. Now `aveThreads.readAt` records when the chat was last on screen, and `ave.markRead` moves it.
- `AveBadge` (was `AveQuestionsBadge`) shows the routed-question count, or else the `UnreadDot` at the same corner when `aveHasUnread` is true. Both the desktop launcher and the mobile header button show it.
- The dot pulses a ring three times as it appears (`.ave-unread-dot`, transform and opacity only, finite), then rests, so a dot left unread costs no GPU time.
- `useMarkAveRead` clears it while the popover or `/ave` page is visible and the tab is in front, mirroring `useChatReadState`.

## Manager Ave suggests next steps and guides new users - 2026-11-04

- `buildAveInstructions` gains "Suggest the next step": after finished, failed or blocked work, Ave offers at most two next steps, and acts only after the user says yes.
- It also gains "Help new users with Eva": a short guide to sessions, quick tasks, projects, automations, schedules, previews and custom instructions, so Ave can answer "how do I…" and say why it picked a kind of work.
- Ave has no project, automation or schedule tools, so the guide points users to those screens. `aveInstructionsContract.test.ts` now checks that the instructions never offer those tools.

## Review fixes before merge - 2026-11-04

- `recomputeProjectPhase`: `completed` / `cancelled` are final only once every project PR is merged or closed. A `completed` from "every task done" with a PR still open reopens when a task does.
- `projectSandboxStarting` returns whether the start still owns the sandbox. `startProjectPreviewSandbox` gives up before creating a VM when it does not, so a workflow retry after a failed attempt no longer leaves a VM behind a closed project. Untokened (interview) starts now take a new attempt number.
- `SandboxIframeService` returns to `idle` when a sandbox swap or stop cancels a start, so the panel can auto-start again and no longer sits on a spinner.
- A stale session start no longer stops the VM a newer start is resuming. The untracked-VM cleanup stops a resumed VM instead of deleting it; it still deletes fresh ones.
- The terminal gives a socket 20 s for its handshake, then treats it as lost, so the reconnect path retries and finally shows "Terminal disconnected" instead of an endless spinner.
- The doc interview and generate starts throw "Another document task is still running" instead of returning quietly, so the dialog clears its loading state and shows its error toast.
- Found on a live sandbox: a superseded start's writes were ignored, but its remaining steps still ran on the VM, and its dev-server relaunch dropped attached terminals. The session, task and project stop predicates now also abort a start whose attempt is no longer current. Their abort handlers no longer stop the VM or clear progress when the start was superseded, because the newer start owns both.

## New skill: find-implicit-state-machines - 2026-11-04

- Added `find-implicit-state-machines` under `.claude/skills` and `.agents/skills`. It is a read-only audit for lifecycles spread across flags, unguarded status writes, stale async callbacks and effect chains. It lists the signals, a verify-before-report step, a report format, and the fix patterns this session used (transition predicates, attempt numbers, terminal-is-final, generation counters, shared derivations).

## Leaks, pending-question access, and four web state machines - 2026-11-03

- **Queue:** a dequeue that consumes a queued message without creating its user message (unresolvable account, failed guard) now deletes its attachment blobs through `_queues/attachments.ts`. `queuedMessages.remove` uses the same helper. The start path still hands the blobs on to the new message.
- **Ephemeral sandboxes:** `prepareSandboxSteps` deletes an ephemeral sandbox it created when a later setup step throws. Callers never received that id, so the arena and automation `finally` blocks could not clean it up.
- **Pending questions:** `pendingQuestions.post`, `getActive`, `answer` and `claimAnswer` check repo access through the repo behind `entityId`. Before, any signed-in user could read, replace or answer another team's blocking question. Ids that resolve to no repo can still be posted and claimed by the sandbox.
- **Turn executing:** a new `isChatTurnExecuting` (`chatBodyUtils.ts`) is the one rule for "is a turn running", used by all seven readers. The design panel, subagent thread and Agents roster now follow the durable turn status, not the last bubble's shape.
- **Terminal:** `TerminalPanel` runs on one `TerminalConnection` union and reducer (`_utils/terminalConnection.ts`). It holds the loading state until the handshake, shows final states for an exited shell and for running out of reconnects, tracks reconnect timers, and keeps the intentional-close flag per socket. Retry now actually reconnects.
  - An exited shell keeps its output visible, with a "Shell exited (N)" bar and Retry below it. Only connection failures replace the terminal with the error view.
- **Skills:** added `.agents/skills` mirrors for `brag`, `brag-slim`, `e2e` and `stageshow` (copied from `.claude`), which fixes `skillsLockMirrorContract`. `brag/assets` (17 MB of music) and stageshow's two example photos are symlinks to the `.claude` copies, so no large media is committed twice.
- **Interviews:** the doc interview and the project interview / spec start generation once per ready message. A failed start or answer clears loading and shows a toast.
- **Dictation:** Stop cancels a dictation that is still connecting. The mic button stays clickable while connecting, so a slow permission prompt can be cancelled.

## Run, automation and sandbox lifecycle follow-ups; web race fixes - 2026-11-03

- A task run now owns only its task's `in_progress` status. `completeRun`, the 2h `handleStaleRun` watchdog and `cancelExecution` no longer overwrite a status the user picked mid-run. The watchdog now keys on `activeWorkflowId`, not on `in_progress`, so it still times out a run whose task was moved.
- Automation run `success` / `error` / `cancelled` are final (`_automations/runStatus.ts`):
  - `updateRunStatus` and `settleEventRun` ignore writes after a terminal status, so a late success can no longer turn a cancel into a success email.
  - `settleEventRun` still advances `eventCursor`.
  - `cancelRun` does nothing on a finished run. Otherwise it closes the agent turn and deletes the ephemeral sandbox, because a cancelled workflow skips its own `finally`.
- Sandbox starts:
  - New sessions boot with attempt 1.
  - Every start request schedules its own failure write 20 min later (`STUCK_STARTING_EXPIRE_MS`). A start whose action died now closes with "Sandbox start timed out. Press Start to retry."
  - A tokened ready that lands after Stop or archive deletes the fresh VM only it made. Untokened prepares (such as `sessionExecuteWorkflow`) keep theirs.
  - An untokened `projectSandboxStarting` (the project interview) may restart a closed sandbox again. This undoes an earlier over-tight guard.
  - Chat release marks a session `closed` only if it is still `active`, and marks its background processes exited.
- Web:
  - Merge and Revert ignore clicks while in flight, and the Merge dialog cannot be closed mid-merge.
  - Force-push marks the offer requested at once and un-marks it on failure.
  - The doc version save keeps edits typed during the save counted, so it no longer shows "saved" over them.
  - `SandboxIframeService` drops results from a start that Stop superseded (a generation counter, as in `CustomTabPanel`). It only cancels polling when the sandbox changes or the panel unmounts.
  - Composer stash and restore share one lock. Stash clears the text up front and puts it back on failure, and removes only the stashed files.

## Parallel awaits on hot paths - 2026-11-02

- Sandbox actions: env vars, credentials, snapshot names, linked repos, preview recovery and mounts now load in parallel; a duplicate credential resolve on preview URLs and code-server is gone.
- MCP agent tools (`get_agent_state`, `list_entities`, chat details, preview URL) and GitHub PR actions run independent reads together; nine PR actions drop a redundant repo read.
- Reactive queries (session/task/project lists, chat status, team members, users, teams, usage limits, routed threads, spotlight) batch independent `ctx.db` reads.
- Chat-turn prompt builds for sessions, tasks and projects fetch chat, user, repo, mentions and sibling repos in parallel.
- Mutation read sets (`hasActiveRun`, `usersShareTeam`), write ordering, workflow steps, the idle-pause sweep (`pause` does not re-check presence) and large GitHub fan-outs (skill sync, app detection) stay sequential on purpose.

## Repo access checks on public doc, project, session and task functions - 2026-11-02

- `authMutation` / `authQuery` only authenticate. These public functions took an id and acted on it with no repo access check, so any signed-in user could use another team's data. They now refuse such callers:
  - `docs.update`, `docs.addInterviewMessage`, `docs.clearInterview`
  - `testGenWorkflow.startTestGen` / `cancelTestGen`
  - `docInterviewWorkflow.startInterview` / `startGenerate`
  - `projectInterviewWorkflow.startInterview` / `startSpec`
  - `projects.startDevelopment` / `createFromTasks`
  - `proposedPlans.capture`, `screenshots.attachMedia`, `sessions.updatePtySession`
  - `repoSnapshots.getSeededAppStatus`, `agentTasks.getStatusesByIds`
- `createFromTasks` also rejects task ids from another repo, because it would move them into the caller's project.
- Deleted `taskWorkflow.triggerExecution`. It had no callers, no access check, and accepted any `repoId`, so it could run a task's prompt against another team's repo.
- New `getDocWithAccess` (`functions.ts`) sits beside the session and project helpers.
- Docs share one `activeWorkflowId` slot. `startTestGen` now refuses while another doc workflow is running, and the interview starts become no-ops. `cancelTestGen` only cancels when test generation holds the slot. "Running" is read from `workflow.status`, so a slot left by a crashed workflow does not block for the 2h watchdog.
- Not changed: `pendingQuestions.post` still has no per-entity check, like `streaming.ts`, because its keys are streaming ids, not entity ids.

## Lifecycle guards for sandboxes, project phase and run status - 2026-11-02

- Deleted five public mutations with no callers that let any client set a status directly: `agentRuns.updateStatus`, `agentRuns.complete`, `sessions.updateStatus`, `sessions.updateSandbox` and `sessions.clearSandbox`. `clearSandbox` dropped `sandboxId` without stopping the VM.
- `recomputeProjectPhase` counts `todo` and `in_progress` tasks as not done again (lost in ec467f624), so one done task no longer completes the project. `completed` and `cancelled` now leave only when a new build starts, not after a task status edit.
- New `_sandbox/transitions.ts` holds the sandbox rules for sessions, tasks and projects. A start request is skipped while the sandbox is `stopping`, and the post-stop drain wakes it again. A start failure closes the sandbox only while it is still `starting`. `projectSandboxStarting` and `projectSandboxAllocated` no longer revive a stopped project; `Allocated` still records the VM id.
- Each start request bumps a new `sandboxStartAttempt` field on sessions, tasks and projects, and passes the number through the startup workflow and action. Ready, failure, `projectSandboxStarting` and `projectSandboxAllocated` writes from an older attempt are ignored. If that older attempt made its own VM, the VM is deleted; a VM shared with the current attempt is kept. Starts with no number (first session boot, the project interview, jobs scheduled before this deploy) keep the status-only rules.
- `markTaskSandboxStartingForChat` no longer turns `stopping` into `starting`. Its return value is unchanged, so journaled workflow runs replay as before. The start action then aborts, and the chat turn reports "did not become ready".

## Feedback on Eva turns: thumbs, agent submit_feedback, Feedback page - 2026-11-02

- New `feedback` table (`convex/feedback.ts`). It has two writers: a user's thumbs on a finished turn (`rateTurn`, one row per user per turn) and the agent's `submit_feedback` MCP tool (`createFromAgent`). The tool exists only on sandbox tokens, like `render_ui`.
- Thumbs up and down sit in the assistant meta row on every chat surface (sessions, quick tasks, projects), because all three use `ChatBody`. A click saves the rating and opens an optional comment box. Clicking the active thumb again clears the rating.
- An agent report shows as a "Feedback sent" card under the reply, in the artifacts slot, so it never moves the prose behind a tab. Anyone who can open the chat can delete the card.
- The new `/feedback` page is in the home sidebar under What's New. It lists the newest 500 rows from every chat the viewer can open, with URL filters (`?sentiment`, `?from`, `?repo`). Each row links to its turn with `?message=`.
- `CHAT_UI_INSTRUCTION` tells the agent to call `submit_feedback` once for each issue of clear frustration or praise, and then to tell the user. `repoIdForSource` moved to `_chatSource/helpers.ts`, so the Log and feedback share one copy.

## Buttons are pills by default (@vvedantb/ui 0.31.0) - 2026-11-02

- `apps/web`, `@eva/ui`, `@eva/shared` and the Chrome extension now use `@vvedantb/ui` 0.31.0. In that release `Button` defaults to `shape="pill"` (`rounded-full`, so icon sizes are circles). `shape="rounded"` keeps the old radius. Eva follows the library default, so the hand-written `rounded-full` overrides can go.
- Eva's Button config moves its radius out of `base` and `size` into `classes.shape` (`pill: "rounded-full"`, `rounded: "rounded-lg"`). One `rounded` string covers every size, so `xs` with `shape="rounded"` gets `rounded-lg`, not its old `rounded-md`. The calendar keeps `rounded-lg`.
- At the default 1rem `--radius`, only `default`, `lg` and `icon` sizes look different; 32px and smaller were already round. With a smaller radius theme, every Button without `shape="rounded"` is now a pill.
- `shape="rounded"` goes on buttons that join other edges or sit in square chrome: the split Run and Build buttons, the PR merge `ButtonGroup`, the file viewer and file tree toolbars, the diff toolbar, env var table rows and provider slots, the sidebar chrome (mobile header, panel close, options menus and their steppers, nav-row action), `BranchSelect`, the doc viewer tab-bar toggles and the gallery `ButtonGroup`s.
- `rounded-full` overrides that repeat the new default are gone: landing CTAs and nav, the page back button, composer stop, PR composer, sketch toolbar, desktop take-control, follow overlay, diff commit chip, comment send, the Conversation scroll and download buttons, and the extension toolbar's inline `borderRadius: 9999`. `ChatNewMessagesPill` keeps only its square inner edges. `PromptInput` `submit` and the composer plus trigger keep `rounded-full`, because `InputGroupButton` uses `shape="rounded"`.
