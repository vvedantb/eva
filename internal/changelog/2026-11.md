# Changelog — November 2026

## Settings no longer list run commands - 2026-11-11

- The App and Snapshots pages drop the read-only startup, background, stop, dev, build and seed lists; one "Commands" section links to the repo's `.eva/config.json` (or offers "Set up with Eva").

## Run commands only change through `.eva/config.json` - 2026-11-10

- The App and Snapshots settings pages show startup, background, stop, dev, build and seed commands read-only; the old editors are gone.
- `updateConfig` and `saveRepoSnapshot` no longer accept command fields, and the internal `setRepoCommandsInternal` / `setSeedCommandsInternal` writers are deleted. Convex keeps the synced copy so a boot needs no GitHub call.
- Cleanup: `migrations:removeRepoSnapshotWorkflowRef` clears the unused snapshot branch field (drop it from the schema after it runs); the never-written `imageFingerprint` field is removed; the Snapshots status tab shows the default branch instead of the stale `workflowRef`.
- An app the file does not list says so and points at the file; a repo without the file shows "Set up with Eva".

## Heavy sessions open from the newest 30 messages - 2026-11-10

- `messages.listByParent` takes an optional `tail`. With it, the query reads only the newest `tail` messages, so its cost does not grow with the chat.
- New `useChatTranscript` hook (`apps/web/src/lib/hooks/`). A chat paints from the tail (30 messages), then takes the full list. Sessions, quick tasks, projects, the subagent roster and the hover prefetch use it. Row ids are the same in both results, so nothing moves when the full list lands.
- The session chat now shows the transcript loader while messages load. It showed "No messages yet" before.
- Load test: the focal chat now carries activity logs sized like production (mean 25.6 KB per assistant message), and 18 `session open` cases cover the queries a session page subscribes to.
- Measured on a 400-message chat (5.6 MB): the query the chat paints from went from 184 ms and 3.1 MB returned to 43 ms and 0.29 MB (30 samples each, Mann–Whitney p < 0.001). The tail reads 34 documents and 0.52 MB at every scale up to 40,000 messages. In Chrome (dev build, cold data), click to last turn on screen went from 787 ms to 520 ms locally and from 1,590 ms to 728 ms at 20 Mbit/s (n = 16 each, p < 0.001).
- Not fixed: the full list still reads the whole chat. It fails at Convex's 16 MiB read limit at about 1,200 messages of this size, and the chat page still errors. The fix is to store activity logs outside the `messages` row, or to page the history.
- Method limit: local server time of the tail still grows with the chat (227 ms at 4,000 messages), because any read in a large index range is slow on the local backend, even `take(1)`. Convex cloud was not measured.
- Deploy notes: none. `tail` is optional, so old clients keep working.

## Quick tasks and projects lists: smaller rows, cheaper reads, hover prefetch - 2026-11-10

- List rows drop `backgroundAgents`, `terminalPanes` and `terminalHistoryTail` (`listRow` in `_validators/listRows.ts`). Only the open task or project panel reads them, from `get`. `backgroundAgents` was 44% of an average task row in production.
- The sidebar quick-task badge uses the new `agentTasks.countSandboxTasks` (sandbox-live rows only, `by_repo_and_sandbox_status`). It replaced `getActiveTasks`, which sent every active task document to the always-mounted sidebar. `getActiveTasks` is removed; it had no other caller.
- `projects.list` reads one chat read row per project up to 1,000 projects (`unreadLookupForList`). Before, a list of more than 50 read the user's whole repo of sessions, tasks and projects. Task lists keep the 50 limit: point reads were slower there and hit 4,096 reads at 1,500 tasks.
- Hovering Quick Tasks or Projects in the sidebar warms the page's queries (route `loader`), as session links already did. `convexPrefetch.ts` holds the shared `prewarm` and `prefetchRepo`.
- Load test (30 samples per side, interleaved): `getAllTasks` returns 264 kB, not 542 kB, at 150 tasks (146 ms, not 177 ms, p < 0.001). The badge query: 24 ms and 2 documents, not 71 ms and 123 documents. `projects.list` at 500 projects: 323 ms and 753 documents, not 1.7 s and 6,128.
- Chrome, dev build, about 720 tasks: hover then click Quick Tasks until a card shows went from 2.68 s to 1.95 s (median, n = 12 each, p < 0.001). The Projects page did not change at 40 projects (p = 0.24).
- Not fixed: `getAllTasks` still reads every task in the repo (2.9 s at 1,500 tasks), and the board renders every card. Paging the board is the next step.
- Deploy notes: none. Old clients that still call `getActiveTasks` get an error in the sidebar badge until they reload.

## Auto-continue once when a chat turn hits the runtime cap - 2026-11-10

- When a session, quick-task chat or project chat turn fails at the 3-hour cap, the turn-end queue drain (`startNextQueuedChatMessage`) puts one continue message at the front of the queue (`queueRuntimeContinue` in `_chat/runtimeContinue.ts`). The chat shows "Continue: the last turn hit the 3-hour limit."; the agent gets a prompt to resume from git.
- One continue per user prompt: a continue that also hits the cap stays failed. The continue copies the prompt's model, account and reasoning, and the chat's sticky thinking, 1M-context and fast-mode traits.
- The runtime-cap error text now lives in `@eva/shared/agentTurnLimits` (`TURN_MAX_RUNTIME_ERROR`, `isTurnMaxRuntimeError`); the Claude, Cursor and Codex daemons and the SDK runners use it.
- Not covered: the first run of a quick task and automations. No new `errorType`, so the failed bubble gets no retry button.

## Agent turn cap raised from 90 minutes to 3 hours - 2026-11-10

- One agent turn may now run 3 hours (`TURN_MAX_RUNTIME_MS` in `@eva/shared/agentTurnLimits`). Long prompts such as load tests with before/after profiling hit the old 90-minute cap (session 430).
- Convex backstops (`RUN_TIMEOUT_MS`: turn lease, workflow watchdog, queue, background-agent hold) now derive from the same file at cap + 30 minutes (3.5 h). Before, they were a separate 2 h, which would have killed a 3 h turn early.
- Removed the quick-task `CLAUDE_MAX_TOTAL_RUNTIME_MS` override; it repeated the default. Token lifetimes (sandbox 24 h, MCP 8 h) stay above the cap.
- Risk: a stuck turn now uses up to 3 hours of tokens before it fails.

## Security: redact tokens from sandbox logs and lock the File Viewer to the workspace - 2026-11-09

WHY: Failed clones, startup commands, runner log tails and turn completions could carry GitHub tokens, API keys or URL credentials into Convex logs and chat. The File Viewer could read or write any sandbox path, including the git credential helper config and `.eva-env.sh`, and a symlink could hop out of the repo. Ported from the stale security PR #767.

Architectural: one `redactSecrets` in `@eva/shared/redactSecrets`, used by the callback bundle and Convex. Callback: `log()`, `buildStepOutput` and `sendTurnCompletion` (`result`, `error`, `rawResultEvent`). Convex: `execHandle` failure text, git exec logs, startup and background command logs, Convex readiness tail, runner log tail (redacted before clipping), watchdog diagnostics (`readKillDiagnostics`). File Viewer reads and writes only under `/tmp/repo`, `/workspace/repo` and `/tmp/workspace`, never a `.git`, `.eva-env.sh` or `git-credentials.env` segment, and resolves symlinks in the sandbox before the same check (`isValidSandboxViewerPath`, `resolveViewerPathScript`). Media harvest uploads only plain single-link files in a real folder. Claude session ids that are not a safe path segment are dropped.

## Jev reads screenshots and long diffs - 2026-11-09

- Jev 1.14 (TypeSafe, 14 Oct 2026) takes images and an opt-in 262k-token context. AI Gateway passes both only through the AI SDK's `experimental_decide`; the old `experimental_evaluate` sent an image as plain text, so Jev answered at chance. `_jev/client.ts` now calls `experimental_decide`. `ai` moved from 7.0.105 to ^7.0.159, and `@ai-sdk/gateway` to ^4.0.132.
- Scope check, screenshots: one more Jev call over the turn's latest four screenshots. It asks whether they show what the prompt asked for, and, for each flagged hunk a user could see, whether that hunk shows in a screenshot. The hover card adds `· visible in a screenshot` to such rows and `· N screenshots checked` to the coverage line. When the screenshots miss the ask, it adds "The screenshots may not show what you asked for." Stored as `scopeCheck.screenshots` and `flagged[].visible`.
- Scope check, whole diff: the headline question now reads up to 180,000 characters, up from 30,000, and sets `longContext` only past 30,000. A 175,000-character real diff (52k tokens) answered in about 0.6 s.
- MCP `evaluate`: new `images` field (up to 4 `{ name, storageId }` from `upload_media`, cited by name in backticks) and `longContext` (state cap 200,000 → 500,000 characters).
- `_jev/images.ts` fits each image inside TypeSafe's 280–1,568 px bounds with `sharp`, a new Convex external package. The Gateway rejects a 1920×1080 capture as "invalid request body".
- Removed the `minimumReleaseAge` exemption for the AI SDK packages; the pinned versions are past the 7-day soak.
- Known gap: media uploads just after the turn completes, and the screenshot pass reads it at the end of the check. A capture slower than the whole check is missed, and that verdict has no screenshot pass.
