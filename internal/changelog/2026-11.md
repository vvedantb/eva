# Changelog — November 2026

## Computer tab can stream with voxl (DESKTOP_STREAMER) - 2026-11-04

- New Convex env var `DESKTOP_STREAMER`: `voxl` streams the sandbox desktop with [voxl](https://github.com/tembo/voxl) (H.264 over WebSocket). Unset or anything else keeps websockify + noVNC. No schema change, so dropping either path needs no migration.
- `VercelDesktop.start` now returns the streamer that actually serves port 16080, and `toggleDesktopServer` passes it to `DesktopPanel`, which loads `vnc_lite.html` for noVNC or `/` for voxl. `StartResult.transformUrl` lets a start override the viewer URL in `SandboxIframeService`.
- A healthy Xvnc display only gets its viewer swapped (env var changed, or the viewer died), so Chrome keeps running. Before, a dead viewer restarted Xvnc too.
- voxl comes from the `voxl-v0.3.2` GitHub release on this repo (built for the Vercel `universal` Ubuntu image, sha256-pinned in `voxlInstall.ts`). It runs behind the auth proxy with its own login off. Where it cannot install or start (AL2023 snapshots, download or checksum failure), the desktop falls back to noVNC.
- Measured in a sandbox at 1920×1080: voxl held about 60 FPS on simulated 10 Mbps and 5 Mbps links, where noVNC got 19 and 10 FPS. voxl used about 0.8 more server CPU cores.

## Feedback on Eva turns: thumbs, agent submit_feedback, Feedback page - 2026-11-02

- New `feedback` table (`convex/feedback.ts`). It has two writers: a user's thumbs on a finished turn (`rateTurn`, one row per user per turn) and the agent's `submit_feedback` MCP tool (`createFromAgent`). The tool exists only on sandbox tokens, like `render_ui`.
- Thumbs up and down sit in the assistant meta row on every chat surface (sessions, quick tasks, projects), because all three use `ChatBody`. A click saves the rating and opens an optional comment box. Clicking the active thumb again clears the rating.
- An agent report shows as a "Feedback sent" card under the reply, in the artifacts slot, so it never moves the prose behind a tab. Anyone who can open the chat can delete the card.
- The new `/feedback` page is in the home sidebar under What's New. It lists the newest 500 rows from every chat the viewer can open, with URL filters (`?sentiment`, `?from`, `?repo`). Each row links to its turn with `?message=`.
- `CHAT_UI_INSTRUCTION` tells the agent to call `submit_feedback` once for each issue of clear frustration or praise, and then to tell the user. `repoIdForSource` moved to `_chatSource/helpers.ts`, so the Log and feedback share one copy.

## Buttons are pills by default (@vvedantb/ui 0.31.0) - 2026-11-02

- `apps/web`, `@eva/ui`, `@eva/shared` and the Chrome extension now use `@vvedantb/ui` 0.31.0. In that release `Button` defaults to `shape="pill"` (`rounded-full`, so icon sizes are circles). `shape="rounded"` keeps the old radius. Eva follows the library default, so the hand-written `rounded-full` overrides can go.
- Eva's Button config moves its radius out of `base` and `size` into `classes.shape` (`pill: "rounded-full"`, `rounded: "rounded-lg"`). One `rounded` string covers every size, so `xs` with `shape="rounded"` gets `rounded-lg`, not its old `rounded-md`. The calendar keeps `rounded-lg`.
- At the default 1rem `--radius`, only `default`, `lg` and `icon` sizes look different; 32px and smaller were already round. With a smaller radius theme, every Button without `shape="rounded"` is now a pill.
- `shape="rounded"` goes on buttons that join other edges or sit in square chrome: the split Run and Build buttons, the PR merge `ButtonGroup`, the file viewer and file tree toolbars, the diff toolbar, env var table rows and provider slots, the sidebar chrome (mobile header, panel close, options menus and their steppers, nav-row action), `BranchSelect`, the doc viewer tab-bar toggles and the gallery `ButtonGroup`s.
- `rounded-full` overrides that repeat the new default are gone: landing CTAs and nav, the page back button, composer stop, PR composer, sketch toolbar, desktop take-control, follow overlay, diff commit chip, comment send, the Conversation scroll and download buttons, and the extension toolbar's inline `borderRadius: 9999`. `ChatNewMessagesPill` keeps only its square inner edges. `PromptInput` `submit` and the composer plus trigger keep `rounded-full`, because `InputGroupButton` uses `shape="rounded"`.

## RollingNumber, SendQueueIcon and useCountUpDisplay come from @vvedantb/ui - 2026-11-01

- `apps/web` and `@eva/ui` now use `@vvedantb/ui` 0.30.2. That release ships `RollingNumber`, `SendQueueIcon`, `useCountUpDisplay` and `parseCountable` (vvedantb/packages #107), so Eva's own copies and its `parseCountable` test are gone.
- Every call site imports from `@vvedantb/ui`. The package code matches Eva's copies: the same spring, the same 220ms count-up, and `RollingNumber` still merges classes with Eva's `cn` through `UiConfig.cn`.
- The composer send button keeps its own children and uses the library `SendQueueIcon`. `PromptInputSubmit`'s `queued` prop only changes the built-in icon, and the upload spinner would need `status="submitted"`, which changes the button label to "Stop".
