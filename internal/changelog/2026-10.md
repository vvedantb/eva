# Changelog — October 2026

## Previews can be served from our own domain so saved passwords carry over - 2026-10-02

- Root cause of "the browser never suggests my preview login": every sandbox preview is `<label>.vercel.run`, and `vercel.run` is on the Public Suffix List, so each preview is its own registrable domain. Browser password managers scope saved logins to that domain and never offer one across previews.
- New Cloudflare Worker (`apps/preview-proxy`) serves `<label>-<sig>.<PREVIEW_PROXY_DOMAIN>` from `https://<label>.vercel.run`: method, headers, cookies and body pass through, a WebSocket `101` is returned as-is so the socket splices straight through, and same-sandbox absolute redirects are mapped back onto our host. All previews then share one registrable domain, so Chrome offers a login saved on any preview on every other one. Eva fills nothing.
- `<sig>` is a 64-bit HMAC-SHA256 of the label (`@eva/shared/previewHost`, plain WebCrypto, imported by both Convex and the Worker so the scheme cannot drift). Without it the Worker would be an open proxy for every Vercel sandbox, and a stranger's sandbox on our domain would be offered the saved password. Unsigned, forged, nested or foreign hosts get a 404 before anything is fetched.
- `getPreviewUrl` moves the URL onto the proxy domain via `toPublicPreviewUrl`; labels that would exceed 63 chars keep the `vercel.run` URL. The `/preview-auth` open-redirect check moved from the web route into `mintPreviewGrant`, which now takes `returnUrl` and returns it with the grant attached — only the backend holds the secret needed to verify proxy hosts.
- Off until both `PREVIEW_PROXY_DOMAIN` and `PREVIEW_PROXY_SECRET` are set in Convex; the Worker needs the same pair (`[vars]` + `wrangler secret put`), its route on the domain, and a proxied wildcard DNS record. The in-sandbox proxy is unchanged: it already turns absolute `*.vercel.run` redirects into path-only ones.
- Checked in local workerd against this session's live sandbox: signed host reached the sandbox's auth gate and served its sign-in interstitial, forged host 404'd without an upstream fetch, and a WebSocket opened through the same splice round-tripped a message.
