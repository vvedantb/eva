## Save selected chat text to Documents - 2026-10-20

- Selecting assistant text now shows Save next to Cite. Save keeps the selection as a note in the chat's Log in the Documents tab.

## Eva PRs no longer get a `draft` label - 2026-10-19

- Session PRs (primary and linked repos) were labelled `eva, session, draft`. The label stayed after ready-for-review, so vvedantb/eva#995 showed `draft` while GitHub's `isDraft` was false.

## Faster agent startup, round 2 (OpenCode fix, Cursor, Claude, Codex) - 2026-10-16

- OpenCode: `OPENCODE_PERMISSION` is now `{"*":"allow"}`. The bare `"allow"` string was deep-merged into `{0:"a",…}`, and on 1.18.16 `GET /config` answered 400, so a cold `opencode serve` never passed the health probe and the turn failed after 60s.
- OpenCode: startup health probes use a 250ms cap and poll every 50ms. A probe in the ~0.3s window before the server can answer hung its full 3s on every cold start. Local cold first text went from 8.7s to 5.7s (n=6). The SDK import overlaps the server start.
- Cursor: each turn worker reads the last model resolution from `model-resolution.json` (key = model config, max age 1h) and refreshes `Cursor.models.list()` (1.3–2.1s) in the background. The SDK imports use Node's compile cache. Local resumed-turn first event went from 5.9s to 4.7s (n=8).
- Claude: `ENABLE_TOOL_SEARCH` is now `"true"`. `"auto"` awaited a `count_tokens` call before the first request, and with MCP still connecting it sent turn 1 without ToolSearch. The GitHub token fetch overlaps the SDK import, and a claimed turn wakes the idle pump. Local daemon start to first token went from 1.69s to 1.31s (n=8, fake API).
- Codex: the lease preflight and GitHub token fetch run in parallel (~80ms). Most of what is left is Codex waiting for MCP servers before the first model call (1.2–1.8s), and Codex has no setting to skip that wait.

## Agent PR watch - 2026-10-16

- Chat-self MCP tools `watch_pull_request` / `unwatch_pull_request` set an optional `watch` on the chat's linked `pullRequests` row (index `by_repo_base_and_watch`).
- Driven by the GitHub webhooks Eva already parses, no polling. A burst schedules one debounced check 60 s later (`watch.checkAt`).
- Triggers: any completed `check_suite` (`parseCiCompleted`), a final commit `status` on the head branch (index `by_head_and_watch`; the GitHub App must subscribe to `status`), trusted feedback, and a base-branch push. A base-branch push re-reads mergeability, because GitHub sends no conflict event.
- The first read only records a baseline, so state from before the watch never wakes the chat.
- `watchCheck` reads state, head, `mergeable` and the check runs (with required flags) in one GraphQL call. `evaluatePrWatch` picks what is new, and the chat wakes through `orchestratorSendMessage`, queued after any active turn.
- Wakes on: newly failed checks, all required checks passed, trusted-human comments or reviews (bots ignored), and new conflicts.
- Ends on merge or close, archive, unwatch, or 10 comment-only wakes in a row. Failed reads retry for 15 minutes.
- An eye button on the PR row in the Review pane stops the watch.

## Faster session switching - 2026-10-13

- Switching between kept-alive sessions re-rendered every mounted session tree three times. Three causes, all fixed at the source:

  - The stock nuqs TanStack adapter selected a fresh object and rebuilt each setter on every pathname change, so every `useQueryState` re-rendered and passed new handlers down. `lib/nuqsTanstackAdapter.tsx` selects a query string and reads the pathname at write time.
