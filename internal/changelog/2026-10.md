# Changelog — October 2026

## Idle sandboxes stop after an hour without chat or agent activity - 2026-10-05

- Vercel bills provisioned memory (2 GB per vCPU, so 16 GB at our 8 vCPUs) for every minute a sandbox runs, idle or not, and nothing stopped an Eva sandbox before its 24h session cap except the user or the opt-in daily sweep. New cron `sandbox idle-stop sweep` (every 5 min, `sandboxIdleStop.ts`) stops any active session, task or project sandbox whose newest chat message (user prompt, assistant reply, or a system alert such as "Sandbox started") is older than the configured idle time. A running turn, run or build, a pending handoff, or a queued follow-up counts as busy and is never stopped. Terminal or preview use that never touches chat does not count, by design.
- Each stop goes through the same path as that surface's Stop button (`requestSessionSandboxStop`, `requestTaskSandboxStop`, and the newly extracted `requestProjectSandboxStop`), so status flips to "stopping" in the same mutation and to "closed" once the provider confirms. A system alert in the chat explains the stop before the usual "Sandbox stopped" divider. The daily sweep's per-surface stops now use the same helpers instead of their own minimal patches.
- Settings → Sandboxes gains an "Idle auto-stop" section (toggle + idle time picker: 15 min to 8 h). Stored on `appSettings` as `sandboxIdleStopEnabled` / `sandboxIdleStopMinutes`; absent means on at 60 minutes, so the sweep is live from deploy. Pure rules in `_sandbox/idleStop.ts`; tests in `tests/sandboxIdleStop.test.ts`.

## Fork session copies the transcript - 2026-10-05

- "Fork session" no longer sends the source's last turns as a `<forked_thread>` first message. The forked Vercel disk already carries every provider's persisted conversation (`/home/eva/.claude-persist` state + transcript, and the Codex/Cursor/OpenCode equivalents), so the fork's first turn resumes the source thread (`resolveClaudeSessionMode`) and the prompt replayed history the agent already had.
- `forkSession` (`_sandbox_runtime/sessionFork.ts`) now pages the source `messages` into the fork with `copyForkMessages` (40 rows a mutation, `clientId` and `pendingQuestion` dropped, everything else verbatim including `model` checkpoints, `afterSha` and storage ids), then `copyForkCards` re-anchors `proposedPlans` and `chatUiPanels` on the copies. The copy finishes before the menu navigates. `createForkedSession` also carries `planContent` and `lastInteractionMode`.
- `collectSessionForkPrefix` removed from `@eva/shared`; the per-message "Fork from here" prompt helpers are unchanged.

## Manager Ave shows mid-run follow-ups in the queue panel - 2026-10-01

- A message sent to Ave while a run is in progress was stored as a transcript row under the still-streaming reply, so it read as already answered. `splitAveFollowUps` (`ave/aveFollowUps.ts`) now holds user rows after the in-flight reply and shows them read-only in the composer's queue panel, as sessions do; they rejoin the transcript when the next run opens its reply.
- `QueuedMessagesPanel` is generic over its row id, and `ChatBody`/`ChatComposer` take an optional `heldFollowUps` list for these server-held rows.
## Preview iframe no longer sticks after a sandbox tab switch - 2026-10-02

- Sandbox tabs hide panes with `display: none` while keeping them mounted. `remeasureAll` (`previewIframeHost.tsx`) skipped 0×0 anchors, so the overlay kept its last rect and stayed painted over the new tab. It now measures every anchored entry; a 0×0 rect hides the overlay.

## Installable desktop app and desktop notifications - 2026-10-02

- `manifest.json`: name "Eva", stable `id`, PNG icon alongside the SVG, no portrait lock; apple-touch-icon now the PNG. Installed windows already take the theme colour for the title bar, so no window-controls-overlay.
- Settings → Notifications → Desktop notifications: per-device opt-in (localStorage + browser permission, `desktopNotifications.ts`). `NotificationToastStream` raises an OS pop-up for unread, non-low arrivals when the window is not focused; `tag` = notification id dedupes across tabs, click focuses Eva and opens it.
- Web Push (pop-ups with Eva closed) is parked; plan in `internal/desktop-notifications-web-push.md`.

## Preview reload spins while the page loads; Browser beam on the pill - 2026-10-02

- The preview reload button shows its spinner while the iframe's document loads, like a browser tab: from iframe mount, a path/reload `src` assignment, or an in-page cross-document navigation (the proxy's nav-sync script posts `eva-preview-unload` on `beforeunload`) until the iframe's `load`. State is a per-element store (`previewDocumentLoading.ts`) shared by `PreviewIframeHost` and `PreviewNavBar`. SPA route changes do not spin. Sandboxes pick up the script change on their next start.
- "Changes in this turn" and PR commit diff dialogs (`DiffEntriesDialogBody`) show the Diffs tab's `DiffFileTree` in a `ResizableSidebar` when more than one file changed; a click scrolls to that file's diff (Files/Diff pane switch on mobile).
- Browser lock: the colourful `BorderBeam` now circles the "Agent is browsing" pill instead of the whole pane; `.beam-inset` removed.

## Fork session (chat + sandbox/DB) replaces Duplicate - 2026-10-01

- Session right-click menus (sidebar row, archived row, Chrome tab) swap "Duplicate" (an empty "(copy)" session) for "Fork session". The fork gets the source's transcript as its first message, plus the source's repo, base, linked repos and composer traits.
- The fork's first sandbox is a Vercel `Sandbox.fork` of the source sandbox (`sessions.forkSourceSandboxId`, new `forkFrom` on `SandboxCreateParams`), not a repo-snapshot boot. Local Supabase volumes, Convex local state and untracked seed files therefore carry over, and the code checks out a fresh branch off the base as usual. Env still comes from Eva's post-create env file. A Vercel fork restores from the source's current snapshot, so `forkSession` (`_sandbox_runtime/sessionFork.ts`) stops a running source first. The source is started again only after the fork's sandbox has been taken. The fork's first boot calls `settleForkSource`, which uses the Start button's path (now shared as `requestSessionSandboxStart`). If the fork fails before the fork session exists, `forkSession` restarts the source itself. A source that was already stopped or archived stays as it was. Forking refuses while a turn is open, and the menu item is disabled with an "Agent working" hint.
- A session with no sandbox (never booted, or archived past the 48h grace delete, which clears `sandboxId`) shows Fork session disabled with a "No sandbox" hint. `forkSession` also refuses when the source sandbox is gone, instead of falling back to a chat-only fork. Only a provider "gone" verdict counts, not any lookup error. If the source is deleted before the fork's first boot, that boot clears `forkSourceSandboxId` and explains why, so the next Start boots the repo snapshot instead of failing forever.
- `messageFork` helpers moved to `@eva/shared` so the backend builds the same `<forked_thread>` prompt. The new `collectSessionForkPrefix` keeps the latest turns that fit the prompt budget.

## Filled icons on active rail tabs - 2026-10-02

- App rail: Inbox, Sessions and Automations take a `filled` prop (`AnimatedNavIcons.tsx`); inner details are painted in `sidebar-accent` (the active tile tone) rather than masked, so hover animations still run.
- Sandbox tab rail: descriptors carry an optional `ActiveIcon` (Tabler `*Filled`), swapped by CSS off the trigger's `data-state`. Icons without one (Browser, Review, Editor, Agents) thicken to a 2.75 stroke. Custom tabs use `TablerIconByName variant="filled"`, which resolves `${name}Filled` or falls back to the bold outline.

## Terminal `claude` matches the agent's CLI; Sonnet 5.5 and Opus 5.5 priced - 2026-10-01

- Launches already install the registry-latest Claude Code / Codex CLI under `/tmp/claude-cli` / `/tmp/codex-cli`, but terminal shells still found the snapshot's older copy first. `createSandbox` now appends `AGENT_CLI_PATH_LINE` (`_sandbox/vercelEnvFile.ts`) to `.eva-env.sh`, putting both install dirs ahead on PATH. The dirs are now exported from `vercelEnvFile.ts` and reused by `launch.ts`. The install guard and `resolvePinnedCliBinary` still compare manifests, so a stale copy first on PATH is still replaced.
- `CLAUDE_PRICING_PER_MILLION` gains `claude-sonnet-5-5` ($2 / $0.20 / $2.50 / $10) and `claude-opus-5-5` ($4 / $0.20 / $5 / $20), read from the Anthropic pricing page on 2026-10-01. Before this, Opus 5.5 prefix-matched the `claude-opus-5` row and was priced at $5 / $25.
