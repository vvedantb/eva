# Changelog — October 2026

## Idle pause: who kept a sandbox awake, and hidden tabs no longer count - 2026-10-07

- Task 262 stayed up for hours with nobody present. The preview proxy counted every browser request as a human, so a background tab with the preview loaded kept resetting the 15-minute idle clock.
- The proxy now injects an on-screen ping into preview documents. It posts once a minute, only while `document.visibilityState` is `visible`. Browser traffic no longer counts by itself; non-browser clients (no `sec-fetch-*` headers: API calls, webhooks) still do. Desktop and editor proxies keep the old rule, because code-server's CSP blocks inline scripts. Proxy `SCRIPT_VERSION` is now `stream-v26`.
- `sandboxActivity` now records `lastUserActivitySource` (chat, start, viewing, preview-tab, preview-page, terminal, files, services) and `lastUserActivityUserId`. Every touch passes its source; actions pass the Clerk subject, and the proxy sends the user from its session cookie. The proxy's `subject` is outside the HMAC, so it is a label, not authorization. A change of source or user skips the one-minute throttle.
- The sweep's `pause` log line prints `lastSource` and `lastUserId`. Presence touches credit the user on the sandbox tab.
- The sandbox Preview region shows "Kept awake by <name> via <source> at HH:mm" (`SandboxLastActivity`, `sandboxIdlePause.getSandboxLastActivity`) while the sandbox runs.
- Prewarm no longer resurrects a stopped sandbox. It polls `isEntitySandboxStopRequested` before each lease-wait probe and before `ensureSandboxRunning`. On 2026-10-07, a prewarm that started before a Stop resumed the VM 8 seconds after the stop, and the sweep could not see it.

## Sandboxes boot Vercel's managed Ubuntu image - 2026-10-07

- Phase 1 of the Managed Images plan (PR #589) shipped only a spike harness; the migration itself was never built. It is now built and on by default — there is no env var or switch.
- `@vercel/sandbox` moved to v3 (main has since taken it to 3.5) — an additive major (`SandboxUser`, `ExecutionContext`, `fork()`, `getOrCreate()`). Nothing eva imports moved and the snapshot `source` variant is unchanged, so restores compile and behave identically.
- `VercelSandboxClient.create` boots every fresh sandbox from `VERCEL_SANDBOX_IMAGE` (`vercel/sandbox/universal:latest`, a constant in `vercelProvider.ts`) instead of the deprecated `runtime: "node24"`. Snapshot restores never pass an image (Vercel forbids it), so existing AL2023 snapshots keep booting as AL2023 until their repo's base Image is rebuilt: on the next nightly build for repos without Stop Commands, on Rebuild Now for the rest. A contract test keeps `runtime: "node24"` from coming back.
- The real work was the ~30 hardcoded `sudo dnf install` sites. Every seeded snapshot in prod is Amazon Linux 2023 and keeps restoring after the change, so the same runtime code (desktop start, the jq bootstrap, `ensureDockerDaemon`, both tmux paths, the whole seed toolchain) has to work on both distros at once.
- `_sandbox_runtime/packageManager.ts` replaces those with one emitted bash helper: `eva_pkg_install` picks the manager present in the image, maps a distro-neutral id through `PACKAGE_ALIASES` (`g++`/`gcc-c++`, `procps`/`procps-ng`, `docker.io`/`docker`, plus Ubuntu 24.04's `t64` ABI renames with their pre-rename names as fallbacks), tries one batch transaction, then retries package-by-package so a drifted name identifies itself in `/tmp/eva-pkg-install.log` instead of failing an anonymous group.
- Vendor installs that differ by more than a package name get their own functions: `eva_pkg_install_chrome` and `eva_pkg_install_gh` (apt keyring + `sources.list` vs `yum.repos.d`), and `eva_pkg_install_file` for code-server, which publishes a `.deb` and an `.rpm` whose asset names differ by more than the extension.
- `_sandbox/ffmpegInstall.ts` keeps its dnf script verbatim — including the pipewire-shim `ld.so.conf` repair — and gains an apt branch, since Ubuntu carries ffmpeg in universe and needs none of the SPAL/libjack workaround. It stays the single source of truth for ffmpeg rather than being duplicated into the package helper.
- The alias table lives in TypeScript and is compiled into the bash `case`, so it is one testable source of truth. Tests resolve candidates by running the generated bash rather than re-implementing the lookup, and `bash -n` parses the helper standalone, newline-joined and `"; "`-joined.
- That last check caught a live bug: `ensureDockerDaemon`'s recovery script joined its lines with `"; "`, putting a literal `;` straight after `sudo setsid dockerd … &` — a bash syntax error. The script never parsed, so the whole Docker recovery path had only ever thrown into its own catch and logged "Docker not available"; the working bootstrap was always the newline-joined `bootstrapVercelDocker` that runs first. It is newline-joined now, and a contract test rejects any `"; "`-joined array containing a backgrounded command.
- The Phase 1 harness has now been run (2026-09-02, throwaway project, resources deleted after): all twelve checks pass, including the AL2023-snapshot-restores-under-v3 blocker. It corrected four guessed apt names (`libgtk-3-0`, `libcups2`, `libatspi2.0-0`, `tigervnc-common` as a separate package) and surfaced two real gaps: the sandbox user differs per image (`vercel-sandbox`/`/home/vercel-sandbox` vs `ubuntu`/`/vercel`), so the interactive `.bashrc` hook now follows `$HOME`; and the seed's `sudo npm install -g` writes to node's prefix while the image preinstalls claude/codex/opencode in the user's. Main had already fixed that split for AL2023 by checking both roots (`globalPackageIsVersion`, `globalNpmRoots()`) and installing Claude/Codex per launch ahead of `PATH`; that design covers Ubuntu too, so no separate fix is carried here.
- A second run restored a **real prod snapshot** (cost-model-ts base, 2.75 GB, written by SDK 2.4.0 on 22 Jul, AL2023, repo and CLIs baked in) under SDK 3.0.0 in 8.1 s. Two facts surfaced: `Snapshot.get` is team-scoped but restore is project-scoped (a 404 means wrong project, not incompatible snapshot), and eva runs one Vercel project per repo.
- Rebuild Now (`startBuild`) now passes `forceImageRebuild: true`. The Snapshots page already said "Rebuild Now always rebuilds the base Image", but apps with Stop Commands only re-seeded, so a base-image change could never reach them from the UI. Scheduled builds stay seed-only.
- That path exposed two bugs in `snapshotBuildWorkflow`, both fixed. First, `config` is read before the base rebuild, so seeding booted from `config.baseSnapshotId`: the previous base, which the rebuild had just deleted. Seeding now uses the id this build captured. Second, the base step called `completeBuild(success)` before seeding, and `completeBuild` ignores non-running builds, so the seed result was dropped and a second Rebuild Now could start in parallel. The base step now only completes the build when nothing follows.
