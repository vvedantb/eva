# Changelog — October 2026

## Fork session (chat + sandbox/DB) replaces Duplicate - 2026-10-01

- Session right-click menus (sidebar row, archived row, Chrome tab) swap "Duplicate" (an empty "(copy)" session) for "Fork session". The fork gets the source's transcript as its first message, plus the source's repo, base, linked repos and composer traits.
- The fork's first sandbox boots from the source sandbox's last-stop snapshot (`sessions.forkSnapshotId`) instead of the repo snapshot. Local Supabase volumes, Convex local state and untracked seed files therefore carry over, and the code checks out a fresh branch off the base as usual. `forkSession` (`_sandbox_runtime/sessionFork.ts`) stops a running source first, because stopping is what writes the snapshot. It refuses while a turn is open.
- A session with no sandbox (never booted, or archived past the 48h grace delete, which clears `sandboxId`) shows Fork session disabled with a "No sandbox" hint. `forkSession` also refuses when the sandbox or its snapshot is gone, instead of falling back to a chat-only fork.
- `messageFork` helpers moved to `@eva/shared` so the backend builds the same `<forked_thread>` prompt. The new `collectSessionForkPrefix` keeps the latest turns that fit the prompt budget.

## Filled icons on active rail tabs - 2026-10-02

- App rail: Inbox, Sessions and Automations take a `filled` prop (`AnimatedNavIcons.tsx`); inner details are painted in `sidebar-accent` (the active tile tone) rather than masked, so hover animations still run.
- Sandbox tab rail: descriptors carry an optional `ActiveIcon` (Tabler `*Filled`), swapped by CSS off the trigger's `data-state`. Icons without one (Browser, Review, Editor, Agents) thicken to a 2.75 stroke. Custom tabs use `TablerIconByName variant="filled"`, which resolves `${name}Filled` or falls back to the bold outline.

## iMessage-style date dividers in the sandbox chat - 2026-10-01

- `ChatBody` heads the first turn of each local day with a centred, text-only label ("Today 9:41 AM", "Yesterday", weekday, or "July 16, 2026"), so sessions, quick tasks, projects and Ave all get it. Boundaries come from `findDayBoundaryIds` (`chatBodyUtils.ts`); the label is `ChatDayDivider`.
- The inbox's private `dayLabel` moved to `formatDayLabel` in `@eva/shared/dates` and is shared by both.

## Re-opened quick tasks preview instead of re-running - 2026-10-01

- A quick task back in `todo` after it has already run now shows the sandbox Start/Stop toggle (like business review) instead of "Run Eva". "Run Eva" stays only for a first run (`todo` with no runs) or an idle `in_progress` task; the card menu item follows the same rule.
- Backend: `isPreviewSandboxAllowed` (`_agentTasks/sandbox.ts`) accepts `todo` when the task has an `agentRuns` row; `startTaskSandbox`, `retryStartupCommands` and `runDevServer` use it. Frontend `canStartSandbox` in `useTaskDetail` mirrors it.

## Terminal `claude` matches the agent's CLI; Sonnet 5.5 and Opus 5.5 priced - 2026-10-01

- Launches already install the registry-latest Claude Code / Codex CLI under `/tmp/claude-cli` / `/tmp/codex-cli`, but terminal shells still found the snapshot's older copy first. `createSandbox` now appends `AGENT_CLI_PATH_LINE` (`_sandbox/vercelEnvFile.ts`) to `.eva-env.sh`, putting both install dirs ahead on PATH. The dirs are now exported from `vercelEnvFile.ts` and reused by `launch.ts`. The install guard and `resolvePinnedCliBinary` still compare manifests, so a stale copy first on PATH is still replaced.
- `CLAUDE_PRICING_PER_MILLION` gains `claude-sonnet-5-5` ($2 / $0.20 / $2.50 / $10) and `claude-opus-5-5` ($4 / $0.20 / $5 / $20), read from the Anthropic pricing page on 2026-10-01. Before this, Opus 5.5 prefix-matched the `claude-opus-5` row and was priced at $5 / $25.

## Unify chat-source docs and artifacts - 2026-10-01

- Backend: `convex/_chatSource/helpers.ts` owns source validators, create-time binding, access check, summary resolution and `by_source_*` listing; `docs.ts` and `artifacts.ts` dropped their copies. `chatSourceFields` is spread into both table schemas.
- Web: `sandbox/chatSource.ts` + `ChatSourceBadge` replace `docs/_source.ts` and `artifacts/_source.ts`; `ChatSourceArg` is derived from the backend args.
- Sandbox panes share `useSourcePanelItem` (one `?panelItem=<id>` param, matched against the pane's own rows), `SessionSourceDetail`, and `SessionSourcePane` now renders "View all" itself (`viewAllHref`).
- `NewDocumentDialog` is shared by the Documents sidebar and the sandbox tab; `useCreateDoc` handles the error toast.

## Notes from the sandbox Documents tab - 2026-10-01

- Sessions, quick tasks and projects: the sandbox Documents tab has a "New" button that creates a doc linked to that chat (title dialog).
- Docs in that tab now open in an inline panel editor (`SourceDocumentEditor`: back button, editable title, live-synced TipTap body) instead of navigating away; the open doc is the `?panelDoc=<numId>` URL param and only opens when linked to the current chat.
- Sandbox Artifacts tab: rows (and the row menu's "Open") show the artifact inline (`SourceArtifactViewer`, `?panelArtifact=<id>`) with back and open-in-new-tab, instead of navigating to `/artifacts/$id`. `ArtifactContent` is shared with the full viewer; both panels share `SessionSourceDetailHeader`.
- Documents sidebar: linked docs show a source pill (chat icon + "Task #12"); hover shows the full chat title.
- Shared helpers: `useCreateDoc` / `useOpenDocInViewer` (sidebar + panel), `useDocSync` + `baseDocEditorExtensions` (viewer + panel editor); `DocSourceArg` now lives in `docs/_source.ts`.
