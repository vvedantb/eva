# Notifications v2.5 (A): reply threads — followers, unread, deep links

- New table `threadParticipants` (root, person, `following`, `lastReadAt`), indexed by root and by person and root. A reply (`sessionWorkflow.addReply`) adds the replier, the root's author (a person), and everyone the root or the reply mentions; Eva's answer adds the person who asked. An Unfollow stays when they join again.
- A reply notifies every following participant (no limit of 3) except the author and the people it mentions, who get the mention ("Priya mentioned you in a thread"). New type `thread_reply` ("Krzysztof replied in a thread"): Updates, toast, push, daily digest. Task and doc comment replies stay `comment_reply` (instant email).
- Eva's answer in a thread notifies the person whose @Eva reply woke her (`turns.askedBy`, set when the thread turn opens). New type `thread_answer` ("Eva answered your question in a thread"): Needs you (Questions), toast, push, daily digest. It reaches the asker even after an Unfollow.
- Notifications carry `threadRootId`. Web: the link opens the project's Replies tab on that thread (`/projects/<n>/sandbox/replies?thread=<id>`). Phone: a push tap, an Inbox row and a Needs you row open `chat/[target]/thread/[rootId]` (push data `thread`).
- Unread per thread (`threads.readState`, `threads.markRead`, shared `useThreadReadState`): "N new" in the mention blue after "N replies" when you follow the thread and others replied since you last read it (web and phone). Inside the thread, the chat's "New" divider sits above the first reply you had not seen. Opening the thread (on screen: web panel and visible tab, phone focus and foreground) reads it and its `thread_reply`, `mention` and `thread_answer` notifications.
- Clearing is scoped: posting in the main chat answers only the main chat's Needs you rows; posting in a thread reads only that thread's.
- Follow / Following in the thread header (web `ReplyThreadView`, phone thread screen; `threads.setFollowing`). Unfollowing stops replies; @mentions still notify.
- Deploy: schema widening only (new table, new optional fields `notifications.threadRootId` and `turns.askedBy`, two new notification types, one new notifications index). After deploy: `npx convex run --prod dataMigrations:backfillThreadParticipants` (idempotent) makes the people of existing threads followers, read up to now. Ship the phone release with the deploy: older apps open the chat, not the thread.
