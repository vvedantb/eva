# Notifications v2.5 (D): email on by default, product updates opt-in, push switch, phone badge

- New `users.notificationPrefs` (`{ email?: boolean; push?: boolean; productUpdates?: boolean }`, sparse). Defaults live in one place, `resolveNotificationPrefs` in `@eva/shared/notificationRouting`: notification email on, push on, product updates off. Desktop pop-ups stay per device (`desktopNotifications.ts`).
- Notification email is one switch, as before, now on by default: urgent notifications email at once and the rest go in the daily digest, as the routing table says (`notificationEmailFor`). Off sends neither. The instant sweep, the digest and the scheduling in `createNotification` / routed mentions all read it.
- Product updates are their own opt-in switch: the weekly changelog broadcast goes only to people who turned it on (`collectProductUpdateRecipients`), so notification email being on by default does not sign anyone up for product news. Other automation emails follow notification email.
- Push off stops every phone push (`push.ts` `schedulePush`), including an agent's blocking question.
- API: `auth.getNotificationPrefs` / `auth.setNotificationPrefs` replace `getEmailNotificationsEnabled` / `setEmailNotificationsEnabled` (deleted; old phone builds lose the email switch).
- Web settings → Notifications: Email → Notifications and Product updates switches (`EmailNotificationsSwitch`, also in the onboarding step); Desktop pop-ups unchanged. Phone settings: the same two switches and a Push switch, in place of "Turn them off in Android settings".
- Phone app-icon badge = Needs you count (`useAppBadge` in `push.ts`, `setBadgeCountAsync`), cleared on sign-out. Push payloads carry no badge: `@vvedantb/server`'s Expo message has no `badge` field.
- Deploy: schema widening only. Right after deploy run `npx convex run --prod dataMigrations:migrateNotificationPrefs` (idempotent): `emailNotificationsEnabled` true → email on and product updates on (the old switch covered the changelog), false → email off (only the settings switch ever wrote false, so it is a choice), unset stays unset; it clears the legacy field. A later PR drops `emailNotificationsEnabled`. Ship the phone release with the deploy.
