# The run system is gone: every task run is a chat turn (phase 2b)

- Deleted the run code: `taskExecutionWorkflow`, `_taskWorkflow/` run lifecycle, watchdog, completion, cancel, start and `runChatTurn`, the `_agentRuns` queries and mutations, the run sandbox claim/attach/finish/abandon mutations, run diagnostics capture, `attachRunId`, and the run branches in turns, turn routing, the chat slot gate, `closeTurn`, turn projection and pending questions. `recovery.ts` keeps only `isSandboxNetworkIssue`; a task's PR is recorded through `_taskWorkflow/taskPr.ts`.
- Stop: `stopTaskRun` (`_agentTasks/taskRunTurn.ts`) drops a queued Run and closes a waiting task's open question; a live Run turn is stopped with the chat and its close hook moves the task.
- `agentTasks.getTaskIdsWithFailedRun` replaces `agentRuns.getTaskIdsWithLatestRunError` on web and phone; `getRunFacts` reads turns only and no longer carries a run PR error (a failed PR shows as a chat alert). `taskRunPending` and the sandbox-held check read task-mode turns.
- `agentTasks.run` keeps only the schedule states. Removed `agentRunActivityLogs`, `messages.runId`, `pullRequests` owner `runId`, and the run-only one-off migrations (`cleanupStaleRuns`, `backfillDeploymentUrlScheme`, the run backfills). The callback no longer uploads media for `RUN_ID` runs (automations had no target for it); the bundle is rebuilt.
- `agentRuns` stays as an empty table until `internal._migrations.deleteRunTurns.deleteRunTurns` removes the old run turns that still name it; a last change then drops the table and that id from `turnEntityIdValidator`.
