# Notifications v2.5 (C): delivery fixes

- One routing table, `@eva/shared/notificationRouting` (`NOTIFICATION_ROUTES`): per type, the Inbox view, web toast and desktop pop-up, phone push, and email (instant, digest, none). `createNotification`, mention routing, the instant email, the daily digest, `NotificationToastStream`, Needs you and "posting in a chat clears it" all read it. Urgency is a modifier on top: `high` toasts, pushes and emails at once; `low` is inbox only; `normal` follows the table, except a chat mention Jev judged fyi, which waits for the digest. The scattered type sets in `notifications.ts` and the toast filters are gone.
- Changes that follow the table: a comment on a task or doc you follow is in the daily digest, not an instant email. "Reply to your comment" (and thread replies, same type) and "Assigned to you" now push to the phone. "Task done", "Status changed" and "Session archived" no longer toast.
- Task and doc comment mentions are created with urgency `normal`: they toast and pop up on desktop at once, push, and schedule the instant email (15-minute debounce). Before, they never toasted.
- A chat mention whose routing fails is now `high` (`notifications.routeMentionFallback`, was `scheduleLegacyMentionEmail`): it toasts, pushes and emails at once. Before, it never toasted.
- The daily digest stamps `emailedAt` on what it sends, so the instant email never sends it again. Its window starts at the previous weekday run (`_notifications/digestWindow.ts`), so Monday's digest includes Friday 08:00 UTC to Monday, weekend included. Subtext reads "Since the last digest".
- Inbox → Needs you shows unread `routed_question` rows and agent `notify_user` messages about a chat (group Questions, web and phone), as for mentions. Posting in that chat, reading or archiving clears them. Row keys are `notification:<id>`.
- Editing a task comment to add an `@`-mention notifies only the people it newly names. Doc comments have no edit path.
- Dead notification types: `export_ready` and `rate_limit` are removed from `notificationTypeValidator` (no rows on prod). `routine_complete`, `run_completed` and `run_failed` still have prod rows (2, 1166, 7 on 26 November 2026), so they stay in the validator as legacy until `dataMigrations:deleteDeadNotifications` has run. After deploy: `npx convex run --prod dataMigrations:deleteDeadNotifications`. A follow-up drops the three literals and their appearance entries.
